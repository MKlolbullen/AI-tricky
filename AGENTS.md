## Evidence asset graph — v1 (2026-11-05)

## Passive ingestion robustness (2026-11-05)
Hardened passive ingestion: (1) **bounded pagination** — adapters that set `pages` (FOFA, ZoomEye) are fetched page by page up to `AI_TRICKY_PASSIVE_MAX_PAGES` (default 3, cap 10), stopping at the first page that yields no records; each page is stored as its own provenance artifact (`passive-<provider>-<qt>-<i>.json`). (2) **rate-limit/quota handling** — `default_passive_http` maps HTTP 429 and 402/403 to clear, non-secret errors that the ingestor records as per-provider coverage gaps (never aborting the whole enrichment). (3) an **in-process TTL response cache** keyed by (provider, query_type, query) with `AI_TRICKY_PASSIVE_CACHE_TTL` (default 900s), so repeated enrichment of the same target reuses responses and does not re-spend provider quota; the per-provider summary reports `source: live|cache`. The opt-in gate and the provider allowlist stay the single enforcement point in `passive_http`. Remaining deferred: graph diffing across enrichment runs; an asset-graph canvas node.

## Asset-graph canvas node (2026-11-05)
Added the `native_asset_graph` workflow node (`Asset graph` in the node library, NATIVE EXECUTION) — a `targets` → `report` node that reads the current asset graph back into a workflow for the entered scope and emits it as read-only DATA, never as live-probe targets (no automatic scope expansion, no target traffic). Backed by `AssetGraph.scope_subgraph(targets, max_entities=2000)`: seeds from the entered targets' hosts (resolved via `scope.parse_target`, so a URL/IP target matches its `host`/`ip` entity — `canonical_asset` keeps a URL's scheme/path and would miss it; CIDR carries no host/ip-entity membership in v1 and is skipped) plus their observed subdomains (`endswith('.'+host)`), walks two hops of typed edges to the attached services/ips/technologies/vulnerabilities/contacts, and returns the bounded `{entities, edges}` slice read-only. The expansion admits only non-host entities — a host reached through a shared IP or technology is outside the entered scope and never joins the slice (no scope leak); the entered seeds are kept first when the entity cap truncates, and the per-hop neighbour scan is bounded. `scope_subgraph` is synchronous SQLite over a connection-local cursor, so the node calls it via `asyncio.to_thread` to stay off the event loop. The node output carries `report` (a one-line "Asset graph for the entered scope: N entities, M relationships (breakdown)" summary, tagged "observed data and third-party claims, not confirmed findings"), the full `asset_graph` sub-slice, and `evidence_status: OBSERVATION`. `execute_workflow` takes an optional `asset_graph=` dependency (threaded from `app.py`); absent it, the node degrades to an empty graph rather than failing. The node auto-appears in the library via `native-registry.json` (no frontend change). Still an observed-data node: it initiates no traffic and asserts no findings. Remaining multi-agent deferrals carry on separately (adaptive role selection; per-member worker isolation).

## Adaptive role selection — multi-agent (2026-11-05)
